# Astrarium observation validation set

The bundled observation set has two targets:

- **M16 / Pillars of Creation:** Hubble WFC3/UVIS calibrated Level-4 FITS mosaics and six JWST NIRCam calibrated Level-3 FITS filters. Both render on the same 200″ WCS grid. Metadata and filter provenance are in each observation folder.
- **HUDF:** four calibrated HUDF12 Hubble WFC3/IR filters, nine calibrated XDF Hubble ACS/WFC and WFC3/IR filters, five calibrated JWST NIRCam JEMS filters, and the independent NASA/ESA Hubble 2014 reference. All telescope renders use the published HUDF center and a 120″ square. The HUDF12 four-band common WHT area is 80.8%; JEMS common WHT area is 77.4%; all nine XDF bands cover the full square. Missing coverage is black. XDF adds five optical filters to the four near-IR filters and supports a much closer wavelength-range comparison with the published deep-field composite.

This is the Astrarium image validation set. HUDF is the deep-field reference case: its Hubble view is checked against the independent NASA/ESA 2014 image, while the co-pointed JWST JEMS view provides a second wavelength-range comparison of shared galaxy positions and morphology. The reference image contains 13 HST filters; the bundled Hubble reconstruction uses four near-infrared bands, so exact color matching is not a pass criterion. The validator also computes registered high-pass morphology scores for M16 NASA-versus-MAST Hubble WFC3/UVIS and JWST NIRCam, between HUDF12 and XDF Hubble renders, and between each Hubble render and JWST JEMS. These scores emphasize nebula or galaxy structure and positions while reducing sensitivity to color stretches; they are alignment checks, not photometric equivalence scores.

The visible-light M16 Hubble view compares the calibrated three-filter MAST WFC3/UVIS SCI composite directly to NASA's 2014 release from proposal 13926 and the same filter set. The release assigns blue to F502N ([O III]), green to F657N (H-alpha+[N II]), and red to F673N ([S II]). The image has no FITS WCS, so the review builder fits a crop and roll from shared image structure; its current registered high-pass correlation is about 0.82 at 360 × 360 pixels. Crop, roll, and residual registration score are stored in `observations/m16-hst/nasa-reference-registration.json`. Per-channel gain and power curves are fitted against corresponding pixels in the approximately registered NASA release, then blended 50% with the previous curves to balance color error and high-frequency morphology. A smooth saturation rolloff in high-brightness regions reduces pink clipping in narrowband star cores while retaining the fitted nebular palette. The reference only calibrates display curves; it is not used as rendered image content. The final gains, exponents, highlight rolloff, and fit residuals are recorded in `observations/m16-hst/metadata.json`. This is a reference-tuned false-color display, not recovered NASA processing or photometric calibration. Rebuild the Hubble image and review with `python3 scripts/build_m16_hst_composite.py` and `python3 scripts/build_m16_hst_review.py`.

The M16 reference case also includes the exact 2015 Hubble WFC3/IR infrared view supplied for comparison. Astrarium coadds the four public MAST visit mosaics in each of F110W and F160W, reprojects the SCI and WHT arrays through FITS WCS, and matches the published 260″ × 243.04″ frame and 35.1° position angle. The render has 98.7% valid common WHT coverage. `artifacts/deep-sky-screenshots/m16-hubble-ir-data-vs-esa.png` compares it with the official ESA/Hubble image; the ESA image is mirrored in the plate to match Astrarium's east-right sky projection. The two-band display maps F110W to blue and F160W to yellow. Per-channel power curves and gains are recorded in the imported observation metadata and affect display only; the underlying coadded SCI samples remain unchanged. Each source mosaic now records its MAST URI, SCI/WHT HDU and byte offsets, cutout bounds, WCS, and valid coverage. Metadata also stores the renderer and source-manifest SHA-256 values and exact command line; the validator checks these hashes and the per-source extraction record. The validation report checks star positions and pillar morphology with a high-pass image correlation at 360 × 337 pixels. This structural score does not validate color or photometric fidelity. The display mapping remains a human-reviewed approximation of the published rendering, not a calibrated reproduction of ESA's color processing.

For an independent input path, `scripts/build_m16_hubble_ir_heritage.py` downloads the original Hubble Heritage F110W and F160W calibrated drizzled SCI mosaics through MAST and reprojects them from their own FITS WCS into the same 260″ × 243.04″, 35.1° frame. Source URIs, input hashes, WCS, cutout bounds, display stretches, and channel curves are saved in its metadata. The image is selectable beside the visit coadd in Astrarium. [NASA's published color key](https://science.nasa.gov/asset/hubble/a-view-of-the-pillars-of-creation-in-visible-and-in-near-infrared-light/) assigns F110W to blue and F160W to yellow; the source files are listed in the [STScI MAST Hubble Heritage archive](https://archive.stsci.edu/prepds/heritage/m16/datalist.html), and the data recipe is in `scripts/m16-hubble-ir-heritage-manifest.json`. The asinh stretch is set to 16; reference-matched channel gains and power curves adjust display only and do not alter SCI values. They are display controls, not a photometric calibration. `artifacts/deep-sky-screenshots/m16-hubble-heritage-reference-comparison.png` shows the published image, visit coadd, and Heritage-SCI render side by side. The updated Heritage render has a 0.744 registered high-pass correlation with the reference (up from 0.731); the display is warmer and closer to NASA’s published image, while its colors remain an approximation. The Heritage mosaic does not provide usable WHT products through the recorded MAST URIs, so this view masks nonfinite SCI values and records that limitation.

Run the structural and provenance checks from the repository root:

```sh
python3 scripts/validate_observation_set.py --report artifacts/observation-validation/report.json
```

The report checks exact filter inventories, manifest dimensions, sky centers, fields of view, calibrated product metadata, weight-map coverage, imported Hubble IR channel provenance and display curves, and that the rendered images contain valid nonempty pixel signal. For M16, HUDF, and both imported Hubble IR views it also reports registered high-pass morphology correlations, residual shifts, and pass thresholds. These metrics emphasize galaxy or nebula structure and source placement while reducing sensitivity to display stretch. They do not measure photometric fidelity or replace human review of color and depth. Rebuild the HUDF review plate with `python3 scripts/build_hudf_review_plate.py`; it compares HUDF12, the independent NASA reference, nine-band XDF, and JWST JEMS. Rebuild the visit coadd plate with `python3 scripts/build_m16_hubble_ir_review.py` and the three-way Heritage plate with `python3 scripts/build_m16_hubble_heritage_review.py`. Review the M16 UVIS/WFC3 and JWST comparison at `artifacts/deep-sky-screenshots/m16-hubble-jwst-direct-comparison.png`.

## Validation checks

1. Select each target and compare the displayed center and field against `observations/validation-set.json`.
2. Compare filter morphology and source placement after WCS projection. M16 Hubble and Webb must share the same celestial center and angular scale. Both are built from calibrated MAST FITS SCI pixels, registered through WCS, and masked with the source WHT coverage where available.
3. Use the NASA HUDF 2014 press image as a broad color and depth reference; it has no FITS WCS and is not pixel-registered to these renders. Check exact galaxy positions and shapes with the WCS-aligned HLF/XDF FITS comparisons instead. Do not require identical color, brightness, or depth: each product's reductions and display processing differ.
4. Confirm that individual filter views retain the structures in their source planes and that no synthetic stars or nebula are introduced in telescope-data mode.
5. Treat the `common_coverage_fraction` (Hubble) and `common_weight_coverage_fraction` (JWST) in each generated metadata file as the valid pixel mask; pixels outside the source mosaic are not observed data.

## JWST HUDF overlap

The same HUDF target now includes five JWST NIRCam JEMS medium-band layers (F182M, F210M, F430M, F460M, F480M). They are fetched as byte-range cutouts from the calibrated MAST SCI and WHT FITS extensions, reprojected with the science-image WCS onto the same 120″ / 1800-pixel output grid as Hubble. Positive WHT samples define each valid area. Each band now uses a 2nd-to-99.8th percentile positive-flux asinh stretch, matching the Hubble XDF treatment; exact SCI flux limits are recorded per filter. The composite averages covered measurements within each color group and records both per-channel and common coverage in `observations/hudf12/jwst-jems-metadata.json`.

Use **JWST JEMS · HUDF 5-filter composite** in the telescope-data selector to compare this view with the Hubble HUDF12 reconstruction and NASA reference. The JEMS RGB assignment is an Astrarium display mapping (F182M blue, F210M green, F430M/F460M/F480M red), not a NASA-published color mapping. Morphology and source positions can be compared; exact color, PSF, and photometry cannot because the filters differ.

To regenerate the cutouts and renders, run `python3 scripts/build_jems_jwst_hudf.py`. The builder reads only the SCI/WHT row ranges that intersect the target field rather than downloading full 2.1 GB mosaics. The source cutout bounds and FITS WCS are saved per filter in the generated metadata.

## Hubble XDF HUDF validation

The XDF layer adds the five ACS optical bands (F435W, F606W, F775W, F814W, F850LP) alongside WFC3/IR F105W, F125W, F140W, and F160W. The builder reads only FITS header and image row ranges needed for the same 120″ field, reprojects each science layer through its WCS, and masks with the inverse-variance weight image. All nine filters cover nearly the full patch. The composite uses NASA's published HUDF 2014 filter-to-color groups restricted to these available XDF bands (F435W/F606W blue; F775W/F814W/F850LP/F105W green; F125W/F140W/F160W red); the four ultraviolet filters in the published 13-filter image are not in XDF. Each calibrated SCI layer uses its own 2nd-to-99.8th percentile positive-flux asinh display stretch. Lowering the former 20th-percentile black point retains much more of the faint positive galaxy signal; the exact black/white flux levels are recorded per filter in the XDF metadata. For the composite, valid filters within a color group are averaged using their WHT masks, so tiny gaps in one band use covered measurements from the other bands in that group. This is display processing, not photometric color calibration.

Regenerate the image layers and metadata with `python3 scripts/build_xdf_hubble_hudf.py`. The PWA selector exposes **Hubble XDF · 9-filter composite** and each individual band. The service worker precaches the XDF layers for offline rendering. NASA's filter-to-color description is on the [HUDF 2014 reference page](https://science.nasa.gov/asset/hubble/hubble-ultra-deep-field-2014/).

## Calibrated JWST M16

The M16 Webb layers come from the actual Level-3 `_i2d.fits` SCI arrays and their WHT extensions, not MAST display JPEGs. The builder applies the positive-WHT mask and each FITS WCS including its PC rotation matrix, then renders six filters with NASA's published purple/blue/cyan/yellow/orange/red assignments. Each filter uses a 10th-to-99.9th-percentile asinh stretch and recorded display gain. A shared asinh luminance curve lifts faint combined signal; final per-channel gain and gamma curves fitted against matching pixels in the approximately registered NASA reference reduce the color error. These display controls do not modify the underlying SCI pixels, and reference pixels are not used in the render. The common valid footprint and all display parameters are recorded in `observations/m16-jwst/metadata.json`. `artifacts/deep-sky-screenshots/m16-jwst-nasa-reference-comparison.png` compares the render to NASA's official release from the same proposal and filters. The review builder estimates a 200″ crop from NASA's approximate 8-light-year image width, mirrors the press image to Astrarium's east-right display, then fits small scale, roll, and translation offsets against high-pass shared star/nebula structure. The current fitted registration is about 0.87 high-pass correlation, with a 1.005× crop-scale adjustment and −2.6° roll; those values are saved in `observations/m16-jwst/nasa-reference-registration.json`. This remains approximate image registration because the NASA PNG has no FITS WCS. NASA does not publish the per-filter stretch and gains on the image page, so color/brightness reproduction remains a documented display approximation. Rebuild with `python3 scripts/build_m16_jwst_composite.py` and `python3 scripts/build_m16_jwst_review.py`.

Select either M16 composite in the telescope-data selector to show Hubble WFC3 and JWST NIRCam side by side on the same center and angular scale. Recreate the JWST output with `python3 scripts/build_m16_jwst_composite.py`. It fetches only the target SCI/WHT byte ranges and caches those cutouts in the ignored `data/m16-jwst-cutouts/` directory, so rerendering does not fetch the source data again.

## Discover and import public MAST observations

Search public calibrated Hubble or JWST products around a sky position, then render one filter or a three-filter false-color composite from those catalog results:

```sh
python3 scripts/query_mast_observations.py --ra 274.721587 --dec -13.841549 --radius-arcsec 120 --mission jwst --output data/mast-m16.json
python3 scripts/render_mast_observation.py --manifest data/mast-m16.json --product-index 3 --field-arcsec 120
python3 scripts/render_mast_observation.py --manifest data/mast-m16.json --blue-index 3 --green-index 4 --red-index 2 --field-arcsec 120
```

The renderer reads only FITS header and SCI/WHT row byte ranges covering the requested footprint, projects each filter onto the same WCS grid, and registers the output in the PWA selector and offline cache. RGB mapping is an illustrative display choice and is recorded with each source product URI and channel stretch in the generated metadata. The structural validator checks imported image content, index/metadata agreement, RGB and Hubble IR channel provenance, and valid coverage; it does not claim exact photometric color agreement.

The Hubble IR Pillars reconstruction is listed as **Hubble WFC3/IR Pillars (F110W blue · F160W yellow)**. It coadds the four 2015 visit products per filter, uses the ESA image center, field, and roll angle, and exposes an in-app side-by-side comparison with the mirrored official reference. The rectangular renderer options (`--height`, `--field-height-arcsec`) preserve a telescope image's native aspect ratio. `--position-angle-deg 35.1` matches ESA/Hubble's published orientation; `--f110w-blue-gain` and `--f160w-yellow-gain` adjust the display mapping, not the source data. Each source URI and per-channel gain is retained in metadata.

## Hubble Legacy Fields HUDF reconstruction

The validation set also includes HLF-GOODS-S v2.0 60 mas calibrated SCI and inverse-variance WHT mosaics in 13 bands: F225W, F275W, F336W, F435W, F606W, F775W, F814W, F850LP, F098M, F105W, F125W, F140W, and F160W. The builder reads only target-intersecting FITS byte ranges, reprojects each filter through its WCS onto the shared 120″ / 1800-pixel HUDF grid, and uses positive inverse-variance weights to mask valid pixels. The composite has 100% common coverage across its three color-channel coverage unions. The color blend uses 12 of those bands; F098M remains individually selectable but is omitted because its valid footprint is 73.4%, which creates an abrupt color boundary. HLF also lacks the ACS/SBC F150LP band used in the NASA 2014 rendering, so color response remains approximate. HLF's published 13-band inventory is documented by [STScI Hubble Legacy Fields](https://archive.stsci.edu/prepds/hlf/); NASA's reference image and color-group descriptions are on the [HUDF 2014 page](https://science.nasa.gov/asset/hubble/hubble-ultra-deep-field-2014/).

Select **Hubble HLF-GOODS-S · 12-band color composite (13 filters available)** or any `HLF · <filter>` layer in the telescope-data selector. Rebuild with `python3 scripts/build_hlf_hubble_hudf.py`; the selector assets are precached for offline use. Compare galaxy locations and broad morphology against NASA, XDF, and JEMS; exact color, PSF, depth, and photometry differ.


The selector also exposes **Hubble HUDF blend · HLF UV + XDF optical/IR**. This display combines the three HLF UV SCI layers with the nine XDF optical/near-IR SCI layers, each registered to the same HUDF grid. The independent XDF layers remove HLF optical/IR mosaic structure from this comparison, while HLF UV bands remain visibly seam-affected. Its filter provenance is recorded in `observations/hudf12/hlf-uv-xdf-composite-metadata.json`; this is a mixed-reduction display, not a single-survey product.

## NASA HUDF 2014 filter inventory

The **Hubble HUDF 2014 · 13-filter composite** uses NASA's full published filter list and blue/green/red assignments. Twelve of the bands come from the calibrated HLF-GOODS-S SCI/WHT products; the missing ACS/SBC F150LP band comes from STScI's calibrated UDFUV science and weight mosaics. The F150LP FITS header is unusually long, so the builder range-reads the header and only the source image rows intersecting the 120″ target, then projects that cutout through its WCS. To reduce the blue background haze from low-significance pixels, HLF and F150LP display layers subtract a 0.75σ floor estimated from `1/sqrt(WHT)` before nonlinear stretching. This is a display-only operation: calibrated SCI arrays and weight masks remain unchanged, and all rendered source structure still comes from the telescope mosaics. The HLF and UDFUV products are later reductions, so the result reproduces the instrument/filter coverage rather than NASA's undisclosed per-filter display parameters. The individual F150LP layer is selectable as well. Rebuild with `python3 scripts/build_hudf_hubble_2014.py` (and `python3 scripts/build_hlf_hubble_hudf.py` for the HLF products); NASA's official filter grouping is documented on the [HUDF 2014 page](https://science.nasa.gov/asset/hubble/hubble-ultra-deep-field-2014/), and the F150LP SCI/WHT products are listed in the [STScI UDFUV archive](https://archive.stsci.edu/prepds/udfuv/).
